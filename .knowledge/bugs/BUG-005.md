# BUG-005: `question_explanations.model_used` mislabeled for all 904 rows

## Summary
`generate_pyq_explanations.py` hardcodes `claude-haiku-4-5-20251001` as the generation model, but
every one of the 904 rows in `question_explanations` has `model_used = 'community_import'` — the
schema default, never overwritten with the real model tag at insert time.

## Impact
No functional/scoring impact (explanations are real Haiku output, just mislabeled). But it breaks
provenance queryability: the new `source_type`/provenance work (PLAN-011) can't distinguish
AI-generated explanations from imported ones by querying this column — undermines the point of
having it.

## Fix
In `generate_pyq_explanations.py`, set `model_used` to the actual model constant at insert time
instead of relying on the schema default. One-line fix; backfill existing 904 rows in the same
migration (`UPDATE question_explanations SET model_used = 'claude-haiku-4-5-20251001' WHERE
model_used = 'community_import' AND <marker that distinguishes AI-generated from any real
community-imported explanations, if any exist>`) — verify no real community-imported rows exist in
this table before blanket-updating.

Cross-project data-provenance audit, 2026-08-30 — see `docs/audit/DATA_AUDIT_2026-08-30.md`.
