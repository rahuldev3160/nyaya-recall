# BUG-003: 2014 PYQ Duplication — DELETE Pending Approval

## Summary
2014 questions were double-ingested from two sources: `12_Paper_2014.pdf` (official, 129
rows) and `community:Aquib-Nawaz` (secondary/community-transcribed, originally 73 rows).
`question_hash` (exact-text hash) found **zero** matches between the two sources — the two
extractions have different punctuation/OCR normalization, so exact-hash dedup doesn't work
here; fuzzy text similarity was needed instead.

## Resolved 2026-09-16 — 17 of ~30 candidate rows deleted, rest deliberately left alone

Rahul approved execution. Backed up first (`~/.claude/backups`, backup id #5) before any
deletion. Method: fuzzy-matched (`difflib.SequenceMatcher`, normalized text) every official×
community pair within year=2014. Found 18 pairs at ≥0.85 similarity; before deleting any,
verified `correct_answer` and full options match/near-match for each pair (not just question
text) — this caught 2 pairs that text-similarity alone would have wrongly treated as safe
twins:
- **community#2329 / official#790**: same question, but `official`'s `correct_answer` is
  **NULL** — deleting community here would have destroyed the only known answer. **Not
  deleted, left as-is**, needs a manual repair decision (which text wording to standardize
  on, and confirming the answer).
- The other 17 pairs had matching (or only cosmetically-differing, e.g. case/apostrophe-style)
  options and answers — safe. Deleted the 17 community-sourced duplicates, kept the
  official-PDF version each time. `2014` now has 129 official + 56 community = 185 rows
  (was 205 before this session's OCR-junk cleanup removed 3, then 202 before this dedup).

**New, separate finding — NOT resolved, NOT part of this fix:** while fuzzy-matching, found 8
community/official pairs (e.g. community#1525/official#920, community#1651/official#865,
community#2019/official#786 — full list in backup #5's context field) where the *official*
row's `question_text` is missing its numbered item list (e.g. official reads only "Which of
the above are famous for the production of traditional sarees/fabric?" while community has
the full "Consider the following towns... 1. Bhadrachalam 2. Chanderi..." stem). This is a
**distinct extraction bug** in the official-PDF ingestion pipeline (multi-part/list questions
lost their enumerated items), not a duplication issue — deleting either side would be wrong
(community has fuller text but isn't the authoritative source; official is authoritative but
incomplete here). Needs its own decision: repair official's `question_text` by merging in
community's list items (after verifying options still line up), or another approach. Not
attempted this session — flagging only.

Remaining ~15 mid-similarity pairs the fuzzy matcher initially surfaced were manually
inspected and confirmed to be **genuinely different questions** that only share generic MCQ
boilerplate phrases ("Consider the following pairs...", "Select the correct answer using the
code given below") — correctly left untouched, not duplicates.
