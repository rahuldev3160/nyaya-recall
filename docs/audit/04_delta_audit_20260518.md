### C5 — self_attestation.py UPDATE on missing SAR row silently drops updates
**Status:** STILL OPEN

**Evidence:**
```python
# scripts/self_attestation.py, lines 61-62
con.execute("UPDATE sar_scores SET sar=?, total_claims=total_claims+1, updated_at=? WHERE user_id=?",
            (result["sar_after"], datetime.now(timezone.utc).isoformat(), user_id))

# lines 68-70
def _update_sar(user_id: str, new_sar: float) -> None:
    con = sqlite3.connect(DB_PATH)
    con.execute("UPDATE sar_scores SET sar=?, updated_at=? WHERE user_id=?",
                (new_sar, datetime.now(timezone.utc).isoformat(), user_id))
```

Both are bare `UPDATE` statements. If `sar_scores` has no row for `user_id` (first use, or wiped DB), the UPDATE matches zero rows and silently succeeds with no error. The fix would be `INSERT OR REPLACE` / `INSERT ... ON CONFLICT DO UPDATE`.

**Assessment:** Not fixed. First-time SAR attestation on a fresh DB will silently discard the SAR update.

### C6 — a["concept_expanded"] KeyError crashes close_session on older DBs (score_engine.py:218)
**Status:** STILL OPEN

**Evidence:**
```python
# scripts/score_engine.py, line 224-226
expanded = list({
    a["subtopic_id"] for a in answers
    if a["concept_expanded"] and a["subtopic_id"]
```

This is a direct key access `a["concept_expanded"]`, not `a.get("concept_expanded")`. On older databases where the `concept_expanded` column does not exist in `session_answers`, `sqlite3.Row` will raise `IndexError` (for row objects) or `KeyError` (once converted to dict via `dict(a)` — which does happen at line 110: `answers = [dict(a) for a in answers]`). The safe fix is `a.get("concept_expanded")`.

**Assessment:** Not fixed. The KeyError/IndexError risk on older DBs remains.

### PROMPT-02 — `{{num_q}}` literal in f-string (quiz.py:283)
**Status:** STILL OPEN

**Evidence:**
```python

return (
    f"Spillover: if all distinct question dimensions for the primary subtopic "
```

`{{num_q}}` in an f-string renders as the literal string `{num_q}` — the double braces are the Python f-string escape for a literal brace. **Assessment:** Not fixed.

### Multi-subtopic cache key is order-dependent (quiz.py:531)
**Status:** STILL OPEN

**Evidence:**
```python
# backend/routes/quiz.py, lines 530-532
def _notes_cache_key_multi(subtopic_ids: list[str], chunk_texts: list[str]) -> str:
    content = "|".join(subtopic_ids) + "|" + "|".join(chunk_texts)
    return "notes_multi:" + hashlib.sha256(content.encode()).hexdigest()[:20]
```

`"|".join(subtopic_ids)` is order-dependent. `["polity", "economy"]` and `["economy", "polity"]` produce different cache keys and will generate duplicate Claude calls. Fix: `sorted(subtopic_ids)` before joining.
